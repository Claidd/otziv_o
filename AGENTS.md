# Единая рабочая ветка и выпуск

По просьбе владельца от 27.09.2026 все изменения проекта собираются в одном
основном каталоге `E:/Works/Projects/otziv`, в ветке `main`.

- Начинайте с проверки состояния основного каталога и актуальности `origin/main`.
  Сохраняйте и учитывайте незакоммиченные изменения других задач. Не создавайте
  отдельные рабочие копии или ветки для обычных исправлений без просьбы владельца.
- Не редактируйте одни и те же файлы одновременно из нескольких задач. Если
  обнаружены текущие изменения, сначала выясните их назначение и сохраните их.
- Законченные изменения фиксируйте в основной рабочей ветке. Если защита GitHub
  требует проверок до обновления удалённого `main`, используйте один временный
  PR для всего накопленного выпуска. Это только транспорт проверки; не оставляйте
  готовые функции в отдельных незавершённых PR. После слияния обновите основной
  каталог до `origin/main`, сохранив всю выполненную работу.
- Перед деплоем сверяйте состав выпуска с запросами пользователя, локальными
  изменениями и открытыми PR. Не обходите незаписанные изменения запуском деплоя
  из чистого клона: именно так раньше терялись доработки при выпуске.
- Деплой запускайте через `deploy.ps1` из основного каталога, после успешного CI
  точной версии `main`. Не отключайте проверки, резервное копирование или защиту
  данных. Проверяйте на VPS и версию, и конкретные запрошенные функции.
- Старые ветки и копии считайте историческими до проверки их содержимого. Не
  сливайте их вслепую и не удаляйте несохранённую работу или используемые Docker
  каталоги. При переносе миграций проверяйте уникальность версии; уже применённые
  миграции не переименовывайте и не изменяйте.

Подробности: `docs/UNIFIED_MAIN_WORKFLOW.md`.
