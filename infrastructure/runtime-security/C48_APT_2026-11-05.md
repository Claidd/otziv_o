# Official Ubuntu apt runtime update (C48)

The 05.11 production image scan reported CVE-2026-109518 (HIGH, fixed) in
`apt` and `libapt-pkg*` of the accepted C45 Keycloak issuer (Ubuntu 22.04,
2.4.14) and the C43 Alloy image (Ubuntu 24.04, 2.8.3). The fixed official
packages are 2.4.15ubuntu0.1 and 2.8.4ubuntu0.1.

C48 inherits each exact parent digest and installs only the two official
Ubuntu packages from `security.ubuntu.com`, pinned by SHA-256:

| Component | Package | SHA-256 |
| --- | --- | --- |
| keycloak | `libapt-pkg6.0_2.4.15ubuntu0.1_amd64.deb` | `3a6fbab029e15ca7b8da642c17ec110995a6e3a0bc40eaa08e239cfc94d6c426` |
| keycloak | `apt_2.4.15ubuntu0.1_amd64.deb` | `2d4db9a3017c5364e50af5bc2f0c76828b52933b682eff4728f1211e081c6736` |
| alloy | `libapt-pkg6.0t64_2.8.4ubuntu0.1_amd64.deb` | `a50f3e68a793f90b05f44a4b5f2f59f3ec7687e39b5d8bbd1da44c84671fa3d6` |
| alloy | `apt_2.8.4ubuntu0.1_amd64.deb` | `ad2ea7f107f250ba88b0bfdba31812a341e3247589647aa2b03b9dc4e8abf8ed` |

`apt-c48-packages.py` records each package's payload and control inventory
with `dpkg-deb` in a network-less container of the parent. Ubuntu's signed
archive index, authenticated by the parent's own `ubuntu-keyring`, reports the
same file, size and digest for all four packages.

Publication runs `42065294809` (Keycloak) and `42065301547` (Alloy) built
commit `5d35c198898be7001769cf6ead6a0f3c2342cd07`, passed the fresh scan of
the exact registry digest and a separate anonymous digest download:

- Keycloak: `ghcr.io/claidd/otziv-security@sha256:2e935efdb594ee4a3f0bc8343b1e6a76def33d70a4981cbd730ce5942ff47009`, 0 HIGH/CRITICAL.
- Alloy: `ghcr.io/claidd/otziv-security@sha256:6010376795977db1a66670feab760e710f70a330f16aa8b2c088367f7ef5861d`; only the two
  unfixed `github.com/docker/docker` findings remain, adjudicated again on the
  exact binary by the unchanged C43 proof.

The stopped-image comparison (`apt-c48-inspection.py`) covers the complete
filesystem including directories, permissions and ownership. Exactly 34 paths
changed in each image: the official apt binaries, methods and libraries, their
changelogs, the newly created `/var/lib/apt/lists/partial`, the documentation
link that the parent's dpkg path filter now omits, package control files and
dpkg/loader bookkeeping. Every other package, the image configuration (except
the publication revision and two `otziv.apt` labels), the Keycloak Java and
provider bytes and the Alloy binary and build closure are unchanged.

Alloy is activated. Its acceptance binds the C43 activation lineage, the
official package bytes, the full filesystem evidence and executed scripts, and
requires the candidate's own adjudication to report the same binary, build
information, closure and function review as C43.

The Keycloak C48 publication and filesystem evidence are retained but remain
held (`apt_c48_keycloak_data_acceptance_required`). The data, authentication
and rollback rehearsal (`apt-c48-rehearsal.py`, unchanged C45 protocol on the
accepted C36 PostgreSQL image) did not run: its read-only capture guard
requires the local prod-like Keycloak network to be `Internal`, and the
current `otziv-prod-local_internal_net` (recreated 05.11 from
`compose.prod-local.yaml`, `driver: bridge`) is not. The guard stopped before
any read. Compose still references the C45 issuer.
