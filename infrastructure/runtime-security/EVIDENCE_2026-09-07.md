## Triage and outstanding review

Every HIGH/CRITICAL row is retained in a `.triage.json` file with its installed/fixed versions, vendor status, report hash, source URL and one review context. `reachability` remains NOT_PROVEN, and risk acceptance/expiry remain null. Context labels are review aids; no CVE is suppressed by them.

- Chromium receives third-party web content in both integrations. Its reported Skia use-after-free (`CVE-2026-85049`) is a priority for vendor/version verification and exposure review. Native XML, image/font, GLib and SQLite findings are also potential runtime dependencies. The sandbox and container limits constrain consequences; they do not prove these vulnerable paths unreachable.
- System-tool findings in Perl, util-linux, mount, gzip, ncurses and systemd need their actual execution/privilege preconditions checked. The app entrypoints do not intentionally run a systemd service or Perl interpreter, and containers drop capabilities with no-new-privileges. That observation is insufficient to exempt every finding from those packages, especially after a process compromise.
- Debian source-package findings may describe code not present in a particular binary package or a platform-specific code path. For example, a zlib entry names a minizip function and a Perl entry names 32-bit builds. Do not turn the title into a false-positive declaration: verify the distro advisory, binary contents, architecture and exact call path before producing a reviewed VEX/exception.

The next release review must assign a real risk owner to unresolved findings, verify vendor fixes and actual exposure, consider a separately tested distribution/runtime migration where necessary, and record any explicitly accepted residual risk with a finite review/expiry date. This file invents neither an owner nor an acceptance policy. The automated available-fix gate passes these image snapshots; residual HIGH/CRITICAL review is still required and the security remediation item is not closed solely by that result.

External Keycloak/MySQL/object-storage/secrets recovery and real external alert delivery remain unproven by this local package. See the explicit prerequisites and drills in the recovery and monitoring runbooks. No external backup job, alert recipient or production rollout was activated.
