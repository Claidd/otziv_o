# Maven dependency and build-tool review

The full Maven gate remains **open**. Updating the application libraries does not close the vulnerable test-only Docker transport, the remaining build-plugin dependencies, or the missing authenticated Sonatype Guide result. No risk acceptance, analyzer disabling, score exemption, or third-party JAR rewrite was used.

## Applied application changes

The application now uses Spring Boot **4.0.8**, with its aligned Spring Framework **7.0.9**, Spring Security **7.0.7**, Spring Data JPA **4.0.7**, Netty **4.2.17.Final**, Jackson **2.21.5 / 3.1.5**, and Log4j **2.25.5**. This is a maintained 4.0.x patch, not a move to the next Boot feature line. See the [official Boot release](https://spring.io/blog/2026/08/20/spring-boot-4-0-8-available-now/), [Framework advisory](https://spring.io/security/cve-2026-47892/), [Security advisory](https://spring.io/security/cve-2026-59270/), and [Data JPA advisory](https://spring.io/security/cve-2026-47834/). Those advisories have specific feature prerequisites; this review does not assert that every reported vulnerability was exploitable in this application's routes.

The newer explicit Tomcat **11.0.25** and HttpCore **5.4.3** versions remain. HttpClient is **5.6.4**, aligned with Core/H2 **5.4.3**; the upstream release notes describe the [TLS and response-resource fixes](https://raw.githubusercontent.com/apache/httpcomponents-client/rel/v5.6.4/RELEASE_NOTES.txt). Connector/J is **26.7.0**, which the [vendor identifies as the successor to 9.7](https://dev.mysql.com/doc/relnotes/connector-j/en/news-26-7-0.html). PDFBox core is **3.0.8**; the [vendor states that CVE-2026-33929 affects the separate examples module](https://pdfbox.apache.org/security.html), so that finding is not evidence that core 3.0.7 had that vulnerability.

Telegram's unused `jersey-container-grizzly2-http` dependency is excluded. The Grizzly vulnerability is genuine and has an [upstream fix](https://github.com/eclipse-ee4j/glassfish-grizzly/releases/tag/5.0.2); it was not suppressed. The app uses the long-polling constructor and does not create a Telegram webhook HTTP server. `TelegramLongPollingDependencyTest` checks the real configuration without Grizzly and runs the actual `TolerantTelegramBotSession` against a loopback HTTP fixture until its update reaches the callback.

Maven Wrapper is **3.9.15**, matching the existing Docker build tool version. Its downloaded ZIP was verified against the official Maven Central SHA-512 before setting `distributionSha256Sum`. This is an explicit alignment choice, not a claim that 3.9.15 is the latest Maven maintenance release. Verification metadata and the original checksum are retained under `.codex-tmp/finalization-20260907/maven-primary-metadata/`.

## Build-tool changes and a scanner limitation

The profile uses **Dependency-Check 13.0.0**, **maven-site-plugin 3.22.0**, and a direct HttpClient **5.6.4** dependency in the Dependency-Check plugin realm. The [official tool release](https://github.com/dependency-check/DependencyCheck/releases/tag/v13.0.0) updates Maven API, Jackson and transport dependencies; the [stable Site release history](https://maven.apache.org/plugins/maven-site-plugin/history.html) supports 3.22.0. No milestone Site version was selected.

`owasp13-actual-plugin-realm.json` records 73 actual loaded JARs by filename and SHA-256, observed after a successful Maven help goal through a read-only EventSpy. It proves that the plugin loaded HttpClient **5.6.4**, Core/H2 **5.4.3**, and Jackson databind **2.22.1**. The proof does not disclose Maven settings or environment values.

Dependency-Check 13's [plugin scanner implementation](https://raw.githubusercontent.com/dependency-check/DependencyCheck/v13.0.0/maven/src/main/java/org/owasp/dependencycheck/maven/BaseDependencyCheckMojo.java) resolves each published plugin artifact's dependency graph without applying the consuming project's plugin `<dependencies>` overrides. Therefore the raw scan still lists its original HttpClient **5.6.3**, even though the observed execution realm contains **5.6.4**. This discrepancy is retained as a tool limitation; it is not suppressed as a foreign-product match and is not used to claim a green gate.
