# Снимки экрана для инструкций сайта

Инструкции «Работа с общим счётом» и «Способ оплаты заказа»
(`frontend/src/app/features/admin/common-billing/common-invoice-guide.component.ts`,
`frontend/src/app/features/manager/order-payment-guide.ts`) показывают шаги на снимках экрана со стрелками и
номерами. Снимки лежат в `frontend/public/assets/guide/light` и `.../dark`, их размеры — в
`frontend/src/app/features/admin/common-billing/guide-shots.ts`. Эти скрипты снимают их заново с локального стенда.

Когда переснимать: изменился вид блока или окна, попавшего на снимок, либо подпись кнопки, на которую указывает шаг.

## Правило: на снимках нет настоящих данных

Стенд работает на копии боевой базы. Файлы из `public/` отдаются без входа, поэтому на снимке не должно быть
настоящих имён сотрудников, названий компаний, телефонов, ИНН и номеров счетов.

- Перед каждым снимком скрипт заменяет их в тексте страницы по правилам из вашего файла настроек.
- Файл настроек содержит настоящие имена (левая часть правила) и хранится вне репозитория.
- Сырые снимки и текст каждого снимка пишутся в рабочую папку вне репозитория (`OTZIV_GUIDE_SHOTS_WORK`,
  по умолчанию — временная папка системы).
- После съёмки просмотрите каждый итоговый снимок глазами и текст рядом с ним (`out/<тема>/<имя>.txt`): всё, что
  похоже на имя или название, должно быть из правой части ваших правил.

## Подготовка

1. Запустите стенд (`infrastructure/scripts/local/prod-like-smoke.ps1`) и включите песочницу оплат:
   `./infrastructure/scripts/local/payment-sandbox.ps1 on`. Без неё окно «Выдать номер карты» не показывает
   рабочее состояние.
2. Откройте отдельный Chrome с отладочным портом и своей папкой профиля и войдите в стенд сами:
   `chrome.exe --user-data-dir=<пустая папка> --remote-debugging-port=9333 http://localhost:8088/`.
   Скрипт паролей не вводит. После съёмки закройте это окно и удалите папку профиля.
3. Скопируйте `local.example.json` за пределы репозитория и заполните:
   - `invoices.issued` — выставленный общий счёт с получателем-сотрудником (номер карты);
   - `invoices.paper` — общий счёт со счётом и актом Точки;
   - `invoices.collecting` — собираемый общий счёт из двух и более заказов;
   - `invoices.bankLink` — выставленный общий счёт со ссылкой банка у менеджера, чей владелец принимает переводы
     на карту (в окне «Оплачен переводом» есть «Владелец»); 0 — снимок `ci-pay-bank-window` не делается;
   - `order` — обычный заказ в статусе «Выставлен счет» с оплатой по номеру карты;
   - `bankLinkOrder` — обычный заказ в статусе «Выставлен счет» со счётом-ссылкой банка у менеджера, чей владелец
     принимает переводы на карту (в окне «Отметить оплату» есть «Владелец»); 0 — снимок `op-paid-bank-window` не
     делается. Чтобы в окне «Выдать номер карты» строка владельца была доступна, остаток месячного лимита его карты
     на стенде должен вмещать счёт заказа `order`;
   - `publishedOrders` — обычные заказы в «Опубликовано» (или в «Публикация» со всеми опубликованными отзывами
     и без задач восстановления: сцена сама нажмёт «опублик.»), берётся первый подходящий;
   - `unpaidOrder` — обычный заказ в статусе «Не оплачено»;
   - `company.withoutLink` — название компании без общего счёта (снимается блок «Общие счета» до включения);
     `company.withSeparateOrder` — название компании, у которой общий счёт уже включён и один заказ остался на
     своём счёте (в блоке видна жёлтая строка «Отдельно остаётся заказ…»). Такую компанию готовят на стенде
     заранее: берут компанию без общего счёта, у которой одному незавершённому заказу уже выдан номер карты,
     и включают ей общий счёт в редакторе;
   - `rules` — замены `[шаблон, флаги, вымышленное значение]` для всех имён и названий, которые видны в этих
     счетах и заказе.
4. Задайте `OTZIV_GUIDE_SHOTS_LOCAL` — путь к этому файлу.

## Съёмка и публикация

```powershell
node infrastructure/scripts/local/guide-shots/scenes.mjs both            # все сцены, обе темы
node infrastructure/scripts/local/guide-shots/scenes.mjs both pay term   # только названные сцены
node infrastructure/scripts/local/guide-shots/scenes.mjs both route route-change
node infrastructure/scripts/local/guide-shots/publish.mjs frontend <версия>
```

- Сцены общего счёта: `panel`, `pay`, `route`, `send`, `term`, `danger`, `paper`, `settings`, `orders`, `company`.
- Сцены обычного заказа: `order`, `orderflow`, `unpaid`, `published`.
- `published` снимается при выключенной песочнице: в песочнице счёт уходит сразу и заказ не задерживается в
  «Опубликовано». Если на стенде такого заказа нет, статус одному заказу стенда ставят на время съёмки в базе
  стенда и сразу возвращают.
- `route-change` вместе с `route` действительно меняет получателя счёта на стенде — так снимается панель
  «после смены» со строкой ожидания отправки. `orders` исключает один заказ из собираемого счёта и возвращает его.
  Обе сцены меняют только базу стенда.
- На системные вопросы страницы («Подтвердите…») скрипт отвечает «Отмена», кроме шага, где сцена сама включает
  согласие (`page.acceptDialogs`).
- `publish.mjs` заменяет снимки в `frontend/public/assets/guide` и записывает `guide-shots.ts`. `<версия>` попадает
  в адрес снимка (`?v=…`), чтобы браузер не показал старый снимок из кэша: укажите дату съёмки.

## Как добавить шаг

1. В `scenes.mjs` добавьте `studio.snap('<имя>', { clip, marks })`: `clip` — что попадает на снимок, `marks` —
   на что указывают стрелки, `n` — номер шага, `side` — с какой стороны стрелка (`left`, `right`, `top`,
   `bottom`; `inside: true` — стрелка рисуется на свободном месте внутри снимка).
2. Снимите сцену и выполните `publish.mjs`.
3. Добавьте фигуру с `shot: '<имя>'` и текстами шагов в нужный раздел инструкции. Номера на снимке — это номера
   шагов сквозь весь сценарий, тест `common-invoice-guide.component.spec.ts` проверяет, что каждый снимок
   использован ровно один раз.
