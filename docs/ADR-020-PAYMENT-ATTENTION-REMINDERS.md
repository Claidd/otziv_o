# ADR-020. Внутреннее напоминание перед просрочкой оплаты

Владелец сценария — management (`personal_reminders`). Раз в пять минут он читает
запланированную дату перехода заказа в «Не оплачено» и за двое суток создаёт
личное напоминание ответственному менеджеру. Напоминание не отправляется клиенту
и не управляет статусом заказа, рассылкой или автоответчиком.

Messaging экспортирует `PaymentDeadlineNoticeSource`: только идентификаторы
действующих задач и проверку даты в текущем платёжном цикле. Orders экспортирует
`PaymentAttentionOrderReader`: скалярный контакт действующего менеджера только для
заказа в статусе ожидания оплаты. Эти API не возвращают ORM-модели и не дают
возможности менять финансовые данные. Вызывающий код — только фоновое задание
management под серверной арендой; пользовательского HTTP-доступа к API нет.

Задание проверяет дату и статус повторно в транзакции создания. Запись напоминания
и признак ручного закрытия принадлежат management; один `stateId` даёт максимум
одну карточку. При оплате, смене платёжного цикла или потере актуальности заказа
карточка закрывается ближайшим проходом задания. Ручное закрытие не создаёт
новую карточку для того же цикла. Ошибка наблюдателя не блокирует платежи и
не влияет на существующую отправку сообщений.
