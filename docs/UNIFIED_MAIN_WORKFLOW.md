# Одна рабочая версия проекта

Основной каталог на этом компьютере: `E:/Works/Projects/otziv`.
Рабочая и выпускаемая ветка: `main`. Все готовые изменения должны попасть сюда
до деплоя. `origin/main` — та же ветка на GitHub, а не отдельный набор функций.

«Группа 1/2/3» в проверках — параллельные части серверных тестов одной версии.
Их разделение ускоряет проверку и не разделяет изменения приложения.

## Обычный выпуск

1. Проверить `git status`, обновить сведения через `git fetch origin`, сопоставить
   локальные изменения и открытые PR с ожидаемым составом выпуска.
2. Сохранить и объединить все законченные доработки в основном каталоге. Не
   заменять этот шаг созданием чистого клона. Запустить проверки затронутых функций.
3. Зафиксировать изменения в локальном `main`. Для обязательных проверок GitHub
   использовать один PR всего выпуска, а не отдельные незавершённые ветки функций.
   Слияние с сохранением коммитов позволяет затем обновить локальный `main`
   командой `git merge --ff-only origin/main` без сброса локальной истории.
4. Дождаться успешных проверок итогового `main`, обновить основной каталог и
   запустить быстрый выпуск `./deploy.ps1 -Tag <название-выпуска> -ImageTransport Direct`
   из него. При явном указании
   `-ProjectFilesRoot` это каталог `E:/Works/Projects`, содержащий `otziv`.
5. Проверить на VPS установленную ревизию, состояние сервисов и каждую ожидаемую
   функцию. Наличие здоровых контейнеров само по себе не доказывает состав выпуска.

Проверка деплоя требует именно `<ProjectFilesRoot>/otziv`, чистый `main`, совпадение
с текущим `origin/main` и успешный CI этой версии. Чистая соседняя копия больше не
служит обходом незаписанных изменений основного проекта.

## Быстрый деплой — обязательный вариант по умолчанию

`deploy.ps1` по умолчанию выбирает прямую доставку (`Direct`) готовых проверенных
образов из CI на VPS. Неизменившиеся образы используются повторно; при установке
перезапускаются только сервисы с изменившимся образом или конфигурацией.
Для обычного исправления не нужно вручную пересобирать всё на компьютере или VPS,
запускать старые сценарии напрямую либо добавлять `-FullRollout`.

`-ImageTransport Local` оставлен для случая, когда прямая доставка недоступна.
Полный режим нужен только при обоснованной технической необходимости; если
автоматический анализ не может доказать безопасное сохранение сервисов, он
указывает причину перехода к полному перезапуску. Пользователю сообщается причина
такого отступления. Проверки CI, резервное копирование и проверка здоровья
сохраняются в быстром режиме.
