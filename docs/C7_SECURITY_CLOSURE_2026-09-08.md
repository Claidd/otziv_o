# C7: исправления по фактическим результатам C6

C6 завершил все шесть Maven-отчётов и обнаружил зависимости, которые не были
помечены предыдущим сканером. Пять отчётов превысили порог CVSS; ошибок
авторизации или квоты Sonatype не было. Из 12 публикаций образов 11 прошли
проверки, а Keycloak остановился на несовпадении Git revision с суффиксом
`-dirty`. Этап анонимного скачивания целиком пропустился из-за этого сбоя.

Точные результаты C6, digest артефактов Actions и исходный manifest сохранены
в [истории публикации](../infrastructure/runtime-security/history/c6/hosted-results.json)
и [неизменённом manifest](../infrastructure/runtime-security/history/c6/reviewed-images.json).
Они описывают завершённый C6 и не являются доказательством прохождения C7.

## Зависимости Maven и issuer

Build-support использует согласованные HttpClient/Cache 5.6.4 и Jsoup 1.23.2.
Старый `net.sf.jtidy:jtidy:r938` заменён официальным
`com.github.jtidy:jtidy:1.0.5`; исключается только старая координата внутри
`maven-plugin-tools-generators`. Политика проверяет точный список исключений
и наличие замены. Обычная сборка, генерация descriptor/helpmojo, API JTidy
и работа HTTP-кэша проверены на фактически разрешённых зависимостях.

В POM provider выравниваются Jackson 2.21.6, Parsson 1.1.9 и Vert.x 4.5.33.
Зависимости provider со scope `provided` не заменяют библиотеки дистрибутива:
Jackson и Parsson обновляются отдельными полными vendor JAR в Dockerfile.
Исходные имена файлов сохраняют сериализованный classpath Quarkus;
контрольные суммы и внутренние метаданные подтверждают новые версии.

Отдельно пересобран официальный модуль CLI Keycloak 26.7.3: он содержит
собственные пять shaded-модулей Jackson, которые не меняются вместе с серверными
библиотеками. Сборка из точного upstream commit меняет только Jackson BOM.
Исходная контрольная сборка воспроизводит все 3 964 файла vendor JAR; в новой
сохраняются 466 классов Keycloak и исходные launcher. Каждая сборка проходит
144 штатных теста, один прежний тест пропущен. Все 25 зависимостей проверяются
по SHA-256. [Полный состав и ограниченные проверки CLI](../infrastructure/runtime-security/proofs/keycloak-cli-c7/README.md).

Промежуточный образ с исправленным сервером сохранил старый CLI. Его исходный
отчёт Trivy показывал ноль HIGH/CRITICAL, но проверка реальных классов выявила
отсутствие исправления. Этот результат сохранён как
[непригодный для активации](../infrastructure/runtime-security/history/c7-server-only/README.md).
Финальная сборка проверяет версии и ограничения JSON именно установленного CLI
с отключённой сетью; ошибка останавливает сборку.

Добавлены два исключения для ошибочных связей конкретных JAR с тремя CVE:
Jackrabbit WebDAV / CVE-2023-37895, CVE-2025-58782 и уже исправленный
Keycloak Services 26.7.3 / CVE-2026-18215. Оба правила связывают точный SHA-1
архива с именованным CVE. Реальный parser и suppression analyzer ODC 13
прошли 217 проверок, включая другие артефакты, версии, изменённые байты и
другие CVE. Это исправление идентификации, а не принятие уязвимости.
Прежние 21 правило сохранены. [Первичные доказательства и границы проверки](../infrastructure/runtime-security/proofs/C7_MAVEN_ADVISORY_PROOF.json).

## Происхождение образов и развёртывание

Provider проходит Maven verify внутри Docker. Публикация проверяет всё
Git-дерево, включая игнорируемые файлы, и сохраняет строгую проверку revision
Buildx. Готовый provider проверяется по SHA внутри точного опубликованного
образа с отключённой сетью и файловой системой только для чтения.

Keycloak дополнительно проверяется по полному списку пакетов Trivy, независимо
от наличия конкретного CVE в базе сканера. Любая обнаруженная старая копия
Jackson или Parsson блокирует публикацию; отсутствие обязательных Java-пакетов
тоже является ошибкой. Анонимная проверка и активация повторяют проверку
сохранённого исходного JSON, включая SHA и image config ID. Этот список может
объединять одинаковые версии из нескольких файлов, поэтому он не заменяет
проверку реального shaded CLI во время сборки.

Анонимные проверки ждут завершения публикаций, но могут проверить успешные
компоненты при сбое соседнего. Отсутствующий или неуспешный отчёт компонента
по-прежнему блокирует его проверку. Для активации требуются совпадающие
commit/run/attempt, digest образа, исходные файлы и необработанные OCI-доказательства
публикации и свежего скачивания без учётных данных. Незавершённый разбор риска
также блокирует активацию; строка `PASS` в публикации сама по себе недостаточна.

[Проверка непрерывности образов БД](DATABASE_IMAGE_CONTINUITY.md) предотвращает
запуск другого image ID на существующем хранилище при rollout и self-heal.
MySQL и PostgreSQL остаются на исходных образах до отдельного согласованного
перехода БД. У PostgreSQL, phpMyAdmin и Alloy сохраняются уязвимости без
доступного исправления; принятие этих рисков не оформлялось.

## Проверка окончательного локального образа

Образ `sha256:d773e1d0de1ef972ba01443a8217d23d6060d2b20d474b3ff84ae2dc840baa54`
прошёл 27 проверок команд CLI без подмены JAR, 20 проверок протокола issuer,
21 сценарий парного восстановления и четыре проверки обычного запуска/import/
start-dev. Проверены все 476 JAR. Trivy сообщил 0 HIGH/CRITICAL; в исходном
отчёте сохранены 33 MEDIUM и 16 LOW. Отдельное правило версий прошло на
исходном JSON и связанном с образом config digest. Это не утверждение об
отсутствии всех уязвимостей. [Отчёт и точные хэши доказательств](../infrastructure/runtime-security/KEYCLOAK_ADVISORY_VALIDATION_2026-09-08.json).

Локальные проверки исходников: 180 тестов инфраструктуры, восстановления и
защитных проверок; 27 тестов политики Maven; 27 тестов непрерывности БД — PASS.
Контракты инфраструктуры и развёртывания, а также actionlint прошли.
[Запись проверки](../infrastructure/runtime-security/proofs/C7_LOCAL_SOURCE_VALIDATION.json).

Новый коммит требует собственных результатов CI и анонимного скачивания.
Прохождение отдельных сборок не закрывает обязательный upstream security gate,
не активирует production и не подтверждает завершение всего плана P01–P21.
