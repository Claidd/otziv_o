# MySQL C37 → C42: исправление Brotli, 27.10.2026

Сканирование main `0b82305a016e3c892c09e2fc6159f589ec1f0ca1` выявило
CVE-2026-111497 (HIGH) в `libbrotli-1.0.9-9.el9_7` и остановило выпуск
исправления мобильного доступа Виктории. C42 обновляет только эту библиотеку
до `1.0.9-10.0.1.el9_8`. Исполняемый файл mysqld, MySQL 9.7.3, все остальные
RPM и текущий PostgreSQL C36 сохраняются.

Точный образ:
`ghcr.io/claidd/otziv-security@sha256:d8b2c5d02611016eee74b77caede5c57a16cd8a1f379bf5c74d322bfd1b5f75d`.
Docker config:
`sha256:b8b1aab82af45b783263e514e2f9746959de78d3a963245cf386720a32b8564f`.
Публикация CI `40494612630` сохранила provenance/SBOM, получила ноль HIGH/CRITICAL
и доказала анонимную загрузку по этому digest без учётных данных.

## Сохранность данных

`mysql-c42-rehearsal.py` проверяет пакет, неизменность SHA-256 сервера и
остальных RPM. Предварительная репетиция использовала существующий
обезличенный снимок от 27.09.2026; итоговая использует отдельный свежий
снимок VPS от 27.10.2026 и опубликованный digest. Обе запускаются без сети
и открытых портов, на собственных одноразовых томах.

Проверки сравнивают все таблицы, количества и контрольные суммы строк,
схему, Flyway, учётные записи и настройки. Дополнительно проверяются вход,
новые записи после перезапуска, откат на C37 с сохранением этих записей
и восстановление свежего дампа на отдельный том. Отчёт содержит только
хэши и количества; дамп в Git не входит. Временный свежий снимок имеет
закрытые ACL и удаляется после успешной итоговой репетиции.

Итоговые доказательства находятся в `infrastructure/runtime-security/proofs/c42-mysql`.
`mysql-c42-readiness.mjs` проверяет цепочку неизменённого C37 и новые
доказательства, включая исходный сценарий и сырой отчёт сканера.
Предварительный локальный образ, изменённые строки/пакеты или исключение
уязвимости не дают разрешения на переход.

## Штатный выпуск

После успешного CI точной версии main из основного каталога:

```powershell
./deploy.ps1 -Tag toria-tmob-brotli-20261027 -ImageTransport Direct -CoordinatedMysqlRefresh -ReleaseSessionToken <token>
```

`coordinated_mysql_cutover.py` выбирает только известный точный переход.
Старый сценарий C30 → C37 не изменён. Для C37 → C42 используется отдельный
`coordinated_mysql_brotli_refresh.py`; флаг перехода PostgreSQL здесь не нужен.
Обычный guard по-прежнему запрещает заменять образ работающей базы.

Перед переходом выпуск проверяет main, ставит deploy lock, останавливает
самовосстановление и создаёт проверенную зашифрованную копию с выгрузкой
с VPS. Затем отдельная процедура останавливает известных писателей,
включает `super_read_only`, сохраняет дополнительную зашифрованную копию,
проверяет её и пересоздаёт только MySQL на том же `docker_mysql_data`.
Все таблицы, схема, Flyway и пользователи должны совпасть до возвращения
писателей. При сбое выполняется откат на C37 с повторным сравнением данных;
если он не доказан, lock и выключенное самовосстановление сохраняются.

Результат на VPS: `.deploy-backups/mysql-c42-cutover-<lock-token>/cutover.json`.
Старый образ и зашифрованные копии сохраняются. После общего выпуска
проверяются здоровье приложения, точная версия main, библиотека Brotli,
миграция 345 и сетевые правила `toria`. Финансовые документы и назначения
компаний этим исправлением не изменяются.
