# Рассылки предложений клиентам

Раздел **Рассылки** (`/admin/client-offers`) доступен владельцу и администратору. Ссылка также есть в пульте автоответчика.

## Использование

1. Создать кампанию, указать название и текст (до 1000 символов).
2. При необходимости добавить один файл до 5 МБ: PDF, TXT, DOC, DOCX, XLSX, PPTX, JPG или PNG.
3. Выбрать способ передачи файла: **Вложением** (по умолчанию) или **Ссылкой на скачивание**.
4. Включить нужные группы: **В работе → На стопе → Бан**. По умолчанию включена только первая.
5. Задать дневной лимит, интервал в минутах и рабочие часы по Иркутску. Кнопка «Посчитать получателей» показывает доступные чаты и компании без настроенного чата.
6. Сохранить черновик либо нажать **Запуск**. После запуска страница может быть закрыта.

Текст, файл и получатели фиксируются при запуске. Новые компании, добавленные позже, попадут в следующую кампанию. Каждый привязанный чат получает предложение один раз за кампанию, даже если к нему относятся несколько компаний. Очередность внутри списка — по ID компании. Статус «В работе» не означает присутствие пользователя онлайн.

## Расписание и результаты

Лимит относится к одной кампании и ограничивает число попыток за календарный день в `Asia/Irkutsk`. Неподтверждённые попытки тоже занимают лимит, чтобы не превысить его при сбоях связи. Неиспользованный лимит не накапливается. Интервал отсчитывается от окончания предыдущей попытки; при нехватке рабочего времени оставшиеся получатели переносятся на следующие дни. Отправки идут ежедневно, включая выходные.

**Пауза** сохраняет очередь; **Продолжить** возобновляет её без сброса дневного лимита. **Остановить рассылку** завершает кампанию и пропускает оставшихся получателей. Уже начатый запрос может завершиться после нажатия паузы/остановки.

Таблица показывает отправленные, ожидающие, пропущенные, ошибки и неподтверждённые результаты. Кнопка **Вернуть ошибки в очередь** работает на паузе или после завершения и касается только случаев, в которых отправка заведомо не началась. После этого нужно нажать **Продолжить**. Неподтверждённые сообщения автоматически не повторяются: необходимо проверить чат.

## Развёртывание

- Применяется Flyway-миграция `V1_10_320__client_offer_campaigns.sql` (кампания, файл и очередь).
- Нужно обновить backend, frontend и WhatsApp gateway. Новый внутренний endpoint gateway — `POST /send-group-file`; он использует существующую авторизацию и журнал операций.
- `client-offers.public-base-url` задаёт адрес сайта для ссылок, по умолчанию берётся `OTZIV_APP_BASE_URL`, затем `https://o-ogo.ru`. Получатель скачивает файл по непредсказуемому токену без входа на сайт; до запуска кампании публичная ссылка недоступна. Скачивание принудительное, с `nosniff` и без кэширования.
- Файлы сохраняются в базе один раз на кампанию. Токен загруженного файла MAX переиспользуется; разрешённый домен загрузки документов — `fu.oneme.ru`, согласно [документации MAX](https://dev.max.ru/docs-api/methods/POST/uploads).
- Используется общий выключатель `client.messages.live-enabled`, с чтением из БД перед отправкой. Кампании не зависят от включения стандартных сценариев автоответчика. При недоступности выключателя отправка приостанавливается.
- Планировщик запускается в отдельном потоке, раз в 10 секунд (`client-offers.tick-ms`). Захват получателя и резервирование лимита транзакционные; сетевой запрос выполняется после коммита. Зависшая более 30 минут отправка становится неподтверждённой, а очередь идёт дальше без её повторения.
- Реальная отправка не выполняется при сборке или тестах. Новые кампании создаются только по действию пользователя и отправляют сообщения только после **Запуска**.

## Проверки

`CampaignStoreMySqlIntegrationTest` проверяет настоящую миграцию, порядок списков, исключения, дедупликацию чатов, лимит, интервалы, паузу, остановку, сбой после захвата, конкурентных работников и неизменность вложения после запуска. Модульные тесты покрывают расписание, файлы, выключатель и выбор способа доставки. Тесты gateway проверяют повторные запросы, неизвестный результат и вложения до 5 МБ. Angular-тесты проверяют форму, ограничения и явный запуск.
