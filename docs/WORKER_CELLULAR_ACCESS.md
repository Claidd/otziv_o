# Доступ специалистов только через мобильную сеть

Ограничение применяется только к пользователям с ролью `WORKER`, у которых нет ролей
`ADMIN`, `OWNER` или `MANAGER`, и только к подразделам:

- `nagul` — «Выгул»;
- `publish` — «Публикация»;
- `recovery` — «Восстановление»;
- `bad` — «Плохие».

Разделы `new` и `correct` остаются доступными с любого подключения. Проверка выполняется
на backend как при загрузке подраздела, так и при прямых вызовах API отзывов и задач.
Для общих API отзыва web и mobile передают текущий подраздел, а backend дополнительно
сверяет статус заказа. Поэтому действия из «Новые» и «Коррекция» не проверяются, а подмена
клиентом защищённого раздела на незащищённый не отключает ограничение.

## Настройки

```properties
OTZIV_WORKER_CELLULAR_ACCESS_MODE=AUDIT
OTZIV_WORKER_CELLULAR_REQUIRE_MOBILE_DEVICE=true
OTZIV_WORKER_CELLULAR_ALLOWED_CIDRS=178.177.216.0/22,178.177.220.0/22,91.78.236.0/22
OTZIV_WORKER_CELLULAR_IP_INTELLIGENCE_ENABLED=true
OTZIV_WORKER_CELLULAR_IP_INTELLIGENCE_BASE_URL=https://api.ipquery.io/
OTZIV_WORKER_CELLULAR_IP_INTELLIGENCE_TIMEOUT=PT3S
OTZIV_WORKER_CELLULAR_IP_INTELLIGENCE_CACHE_TTL=PT24H
OTZIV_WORKER_CELLULAR_VIOLATION_STATISTICS_ENABLED=true
OTZIV_WORKER_CELLULAR_VIOLATION_EPISODE_WINDOW=PT30M
OTZIV_WORKER_CELLULAR_VIOLATION_RETENTION_DAYS=90
OTZIV_WORKER_CELLULAR_COUNT_UNKNOWN_NETWORK_VIOLATIONS=true
OTZIV_WORKER_CELLULAR_VIOLATION_STATISTICS_VISIBLE_TO_MANAGERS=true
OTZIV_WORKER_CELLULAR_ENFORCED_REASONS=NON_CELLULAR_NETWORK,VPN_PROXY_OR_DATACENTER
OTZIV_WORKER_CELLULAR_ENFORCE_NATIVE_VIRTUAL_DEVICE=true
```

`OTZIV_WORKER_CELLULAR_ALLOWED_CIDRS` — разделённый запятыми список IPv4/IPv6 CIDR,
которые подтверждены как мобильные сети используемых операторами специалистов. В текущий
список добавлены NAT-пулы MegaFon `178.177.216.0/22` и `178.177.220.0/22`, а также мобильный
пул МТС Иркутска `91.78.236.0/22`. Реестр RIPE обозначает первые два диапазона как
`SIB-OMK-NAT-MF`, а диапазон МТС — как `PJSC "MTS" Irkutsk MBN`. Используемый бесплатный
ipquery может ошибочно возвращать для этих диапазонов `is_mobile=false`. Обратное имя
`ppp*.pppoe.mtu-net.ru` у адреса из подтверждённого MBN-пула не считается доказательством
домашней сети.

Для добавления других подтверждённых диапазонов сохраните текущие значения и допишите новые:

```properties
OTZIV_WORKER_CELLULAR_ALLOWED_CIDRS=178.177.216.0/22,178.177.220.0/22,91.78.236.0/22,192.0.2.0/24
```

Последний адрес в примере является документационным и не должен использоваться в production.
Новые диапазоны следует получать у операторов или из поддерживаемой организацией базы IP/ASN.
Совпадение CIDR подтверждает только мобильную сеть. Проверка VPN/дата-центра и проверка
устройства выполняются отдельно: обычный мобильный браузер проходит, а desktop User-Agent
остаётся `DESKTOP_OR_UNKNOWN_DEVICE` и записывается как предупреждение.

Режимы:

- `OFF` — проверка выключена;
- `AUDIT` — решение и обезличенный префикс IP записываются в журнал, запрос не блокируется;
- `ENFORCE` — HTTP 403 получают только причины из `OTZIV_WORKER_CELLULAR_ENFORCED_REASONS`
  и подтверждённый нативным приложением эмулятор, если
  `OTZIV_WORKER_CELLULAR_ENFORCE_NATIVE_VIRTUAL_DEVICE=true`. Остальные нарушения продолжают
  записываться как аудит без блокировки.

При включённом `IP_INTELLIGENCE` backend запрашивает у ipquery признаки мобильной сети,
VPN, proxy, Tor и дата-центра. Успешный ответ кэшируется на 24 часа, поэтому внешний запрос
не выполняется при каждом открытии страницы. Доступ разрешается только при `is_mobile=true`
и отсутствии рискованных признаков. При ошибке внешнего сервиса сеть получает
`UNKNOWN_NETWORK`; блокировать ли эту причину, определяет список `ENFORCED_REASONS`.
Подтверждённые вручную CIDR остаются резервным источником.

Настройки читаются при запуске backend, поэтому после изменения контейнер приложения нужно
перезапустить.

## Сигналы мобильного приложения

Нативное приложение добавляет к запросам нашего backend тип текущего подключения
(`cellular`, `wifi`, `none`, `unknown`), платформу, модель, признак эмулятора, версию приложения
и сокращённый идентификатор установки. Эти данные учитываются только при проверке защищённых
подразделов и сохраняются как основание эпизода нарушения.

Сервер не разрешает доступ только по заявлению приложения: публичный IP по-прежнему должен
быть подтверждён как мобильный и не иметь признаков VPN/proxy/Tor/дата-центра. Сообщение
`wifi` считается `NON_CELLULAR_NETWORK`, `isVirtual=true` — `DESKTOP_OR_UNKNOWN_DEVICE`,
а отсутствующий или неопределённый тип сети — `UNKNOWN_NETWORK`. Старые версии приложения
без телеметрии продолжают проверяться по User-Agent и публичному IP.

Для нативного Android/iOS-приложения физическое устройство определяется по сочетанию
поддерживаемой платформы и `isVirtual=false`, без зависимости от User-Agent отдельных
HTTP-запросов. User-Agent используется только для браузеров и старых приложений. Это важно,
поскольку нативный HTTP-стек одного приложения может отправлять разные User-Agent.

## Статистика нарушений в «Моей команде»

Неуспешные проверки сохраняются в таблице `worker_network_violation_episodes`. Повторные
обращения одного специалиста с одинаковой причиной в одном подразделе объединяются в
30-минутный эпизод. В карточке сотрудника доступны отдельные итоги за выбранный день и месяц:
число эпизодов, число попыток, дни с нарушениями и последние 20 эпизодов.

На UI технические коды не выводятся. Пользователь видит русские причины: «Домашняя сеть или
Wi-Fi», «VPN, прокси или анонимная сеть», «Компьютер или неподдерживаемое устройство» и
«Не удалось определить сеть». Полный IP в таблице не хранится — только маскированный префикс.
По умолчанию записи удаляются через 90 дней. Статистика доступна владельцу и администратору,
а менеджеру — только по специалистам, уже входящим в его команду.

Миграция `V1_10_111` сохраняет ранее ошибочно созданные эпизоды физического нативного
телефона с `network=cellular`, но помечает их `INVALIDATED`. Такие записи остаются в БД для
аудита и больше не входят в статистику «Моей команды».

Миграция `V1_10_118` так же исключает из статистики старые `NON_CELLULAR_NETWORK` для
подтверждённых мобильных NAT-пулов MegaFon `178.177.216.0/22` и `178.177.220.0/22`.

Миграция `V1_10_119` исключает из статистики старые `NON_CELLULAR_NETWORK` для
подтверждённого мобильного пула МТС Иркутска `91.78.236.0/22`. Исходные эпизоды остаются
в таблице с результатом `INVALIDATED`.

## Рекомендуемое включение

1. Оставить в списке только уже подтверждённые CIDR, включить IP intelligence и `AUDIT`
   минимум на один рабочий день.
2. Убедиться, что backend пишет события `Worker cellular access`, но никого не блокирует.
3. Попросить специалистов открыть каждый рабочий подраздел с отключённым Wi-Fi и VPN.
4. Собрать сводку обезличенных префиксов из production-логов:

   ```powershell
   .\infrastructure\scripts\prod\summarize-worker-cellular-audit.ps1
   ```

   Если логи находятся не в `data/app-logs`, передать путь через `-LogPath`.

5. Убедиться, что домашние сети получают `intelMobile=false`, а мобильные операторы — `true`.
6. CIDR добавлять только как резерв для подтверждённых ошибок классификатора.
7. Проверить журнал `Worker cellular access` для IPv4 и IPv6.
8. Дополнить или исправить диапазоны.
9. Оставить в `ENFORCED_REASONS` только подтверждённые причины: сначала немобильную сеть и
   VPN/proxy/datacenter. `DESKTOP_OR_UNKNOWN_DEVICE` и `UNKNOWN_NETWORK` оставить в аудите.
10. Включить `ENFORCE` и выполнить smoke-тест под ролью `WORKER`.

Для экстренного отката достаточно вернуть режим `OFF` и перезапустить backend.

## Важные ограничения

Для браузера проверка устройства основана на `User-Agent` и `Sec-CH-UA-Mobile`, для нативного
приложения — на платформе и признаке эмулятора. Мобильная сеть проверяется по типу
подключения приложения и публичному IP после доверенного reverse proxy и данных ipquery.
IP передаётся этому внешнему сервису только при первом обращении или после истечения кэша.
Клиентскую телеметрию можно подделать в модифицированном приложении, поэтому это
организационное ограничение, а не криптографическое подтверждение SIM-карты.
