# Удаление заказа из редактора и состав общего счёта

Владелец сценария удаления — модуль orders. Модуль billing предоставляет
`CommonInvoiceOrderDeletion`: `lockForOrderDeletion` получает блокировки без
изменений, затем `detachForOrderDeletion` выполняется после проверки права
пользователя на удаление. Обе операции требуют транзакцию вызывающей стороны.

Порядок блокировок сохраняется для всего состава счёта: заказы по возрастанию ID,
платёжные ссылки, расчётная группа и счёт. Между предварительным чтением и захватом
блокировок принадлежность проверяется повторно; её изменение завершает команду
конфликтом. Заказ без активного счёта блокируется отдельно с повторной проверкой
принадлежности. Вход в этот путь не создаёт платёж и не отправляет сообщение.

Для неотправленного счёта допускается штатное исключение позиции с проверкой
платёжных данных всех позиций, банковских попыток, неизвестных отправок и резервов.
Используется та же политика состава, что для явного исключения из общего счёта.
После исключения пересчитываются сумма, готовность и предупреждения счёта.
Исторические позиции и финансовые доказательства не удаляются этим обходом.

Удаление заказа, его зависимостей, исключение позиции, пересчёт и освобождение
неиспользованного резерва входят в одну транзакцию. Ошибка на любом последующем
шаге откатывает весь результат. Роли и доступ к компании остаются в существующих
границах ADMIN/OWNER/MANAGER. Подтверждение интерфейса описывает удаление заказа
и отзывов, исключение из неотправленного счёта и пересчёт; отмена не вызывает API.

Перед установкой этот сценарий проверяется в штатном локальном Docker со свежей
копией БД VPS. Действия с реальными производственными заказами для проверки не выполняются.
