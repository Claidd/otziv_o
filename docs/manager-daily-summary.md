# Ежедневная сводка менеджеров

## Точка возврата

- исходный коммит: `4fd5b4ef`;
- Git-тег перед началом разработки: `before-manager-daily-summary-20260713`;
- ветка разработки: `codex/manager-daily-summary`.

При проблеме сначала отключить рассылку и очистку в `app_settings`:

```sql
UPDATE app_settings SET setting_value = 'false'
WHERE setting_key IN ('manager.summary.enabled', 'manager.summary.cleanup-enabled');
```

После этого приложение можно сравнить или вернуть к тегу. Новые таблицы можно оставить: старая версия приложения их не использует. Удалять таблицы при аварийном откате не требуется.

## Безопасный порядок включения

1. Развернуть миграцию `V1_10_89` с выключенными рассылкой и очисткой.
2. Открыть контроль менеджеров и нажать «Предпросмотр ночной сводки».
3. Проверять дневные строки и текст 10–14 рабочих дней.
4. При необходимости задать белый список пользователей в `manager.summary.recipient-user-ids`.
5. Включить `manager.summary.enabled=true` только для владельцев и администраторов.
6. Не включать `manager.summary.manager-groups-enabled` до окончания пилота.
7. Включить `manager.summary.cleanup-enabled=true` только после накопления минимум 90 дней проверенных дневных агрегатов.

## Расписание

- `22:55` — предварительный снимок;
- `00:00` — финализация завершившегося дня и закрытая Telegram-рассылка;
- `03:45` — очистка по retention-политике;
- зона по умолчанию — `Asia/Irkutsk`.

Cron и зона задаются переменными `MANAGER_SUMMARY_SNAPSHOT_CRON`, `MANAGER_SUMMARY_DELIVERY_CRON`, `MANAGER_SUMMARY_CLEANUP_CRON`, `MANAGER_SUMMARY_ZONE`.

Ночная сводка включает фактический разбор клиентских сообщений и рисков: ручные и автоматические
закрытия, быстрые серии действий, качество ответов, конкретные спорные случаи, SLA и аудит решений.
DeepSeek получает ограниченную выборку переписки и формирует обучающий разбор; при недоступности
модели числовая часть и примеры отправляются без AI-комментария. Управление:
`manager.summary.ai-analysis-enabled`, таймаут — `manager.summary.ai-analysis-timeout-seconds`.

## Рейтинг

Официальная формула остаётся прежней, включая поправку на нагрузку. Изменена только шкала категорий:

| Баллы | Категория |
|---:|:---:|
| 90–100 | A |
| 80–89 | B |
| 70–79 | C |
| 60–69 | D |
| 50–59 | E |
| 40–49 | F |
| 30–39 | G |
| 20–29 | H |
| 10–19 | I |
| 0–9 | J |

Новые показатели ответов пока собираются в дневном теневом контуре. Они не меняют официальный балл до завершения контрольного периода.

## Активность и сообщения

- сайт отправляет heartbeat только при видимой вкладке и недавнем действии пользователя;
- после 15 минут без новых событий начинается новый активный интервал;
- мессенджеры считаются отдельно;
- общая подтверждённая активность строится объединением интервалов без двойного учёта;
- ответы считаются в рабочих окнах `manager.summary.workday-start`, `manager.summary.workday-end`, `manager.summary.working-days`;
- повторные входящие сообщения до ответа объединяются в один период ожидания.

## Хранение

- `manager_site_activity_events` — сырые события сайта, 90 дней;
- `client_chat_messages` — метаданные сообщений, 90 дней;
- текст сообщений обезличивается через 30 дней;
- `manager_performance_daily` — дневные результаты;
- `manager_performance_monthly` — месячные агрегаты;
- `manager_performance_yearly` — годовые агрегаты;
- `manager_summary_delivery_log` — доставка, 180 дней.

Удаление выполняется пакетами и не затрагивает открытые ожидания ответа. Месячные и годовые средние строятся из сумм и количества событий, а не из средних дневных значений. Распределение времени ответа хранится в семи диапазонах, поэтому сырые сообщения не нужны для многолетней динамики.

## API владельца и администратора

- `POST /api/admin/manager-daily-summary/calculate?date=yyyy-MM-dd` — пересчитать день;
- `GET /api/admin/manager-daily-summary?date=yyyy-MM-dd` — получить дневные строки;
- `GET /api/admin/manager-daily-summary/preview?date=yyyy-MM-dd` — получить текст предпросмотра.

Мотивация, награды и новые правила XP намеренно не включены в этот этап.
