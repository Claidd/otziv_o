# Пауза между сменой и блокировкой аккаунтов

В «Справочники → Настройки → Смена и блокировка аккаунтов» администратор или владелец управляет переключателем «Таймер включён» и длительностью в секундах: целое число от 0 до 3600. По умолчанию таймер включён на 60 секунд. Выключение переключателя снимает ограничение, сохраняя выбранную длительность. Значение 0 также отключает ограничение независимо от переключателя. Изменения применяются после сохранения настроек.

Новая длительность применяется к следующему принятому действию; срок уже начавшейся паузы сохраняется. Пока таймер выключен, действия не ограничиваются и не создают новую паузу. При повторном включении до истечения прежней паузы действует её оставшийся срок.

Ограничение относится к авторизованному пользователю с ролью `WORKER`, у которого нет `ADMIN`, `OWNER` или `MANAGER`. Оно общее для обычных отзывов, задач восстановления, плохих отзывов, деталей заказа и старых MVC-страниц при включённом legacy-интерфейсе. Ручное назначение «Новый аккаунт» использует тот же допуск. Внутренние каскадные замены учитываются один раз; автоматическое переназначение после редактирования отзыва не считается нажатием кнопки.

## Поведение

- Первое допустимое действие выполняется сразу. Обе кнопки во всех карточках специалиста временно недоступны.
- Подтверждение «Блок» можно отменить без запуска паузы. Проверки доступа, существования объекта и актуальности блокируемого аккаунта выполняются перед допуском.
- Принятая попытка расходует паузу, в том числе если свободный аккаунт не найден. Ошибка основной бизнес-транзакции не стирает запись допуска.
- Повторный запрос во время паузы возвращает HTTP 429 с кодом `WORKER_ACCOUNT_ACTION_COOLDOWN`; отклонённые попытки не продлевают срок.
- Навигация и остальные действия сохраняют существующие правила доступа. Тост остаётся сверху, включая мобильные экраны, и не перехватывает клики.
- Состояние переживает переходы, перезагрузку страницы и смену вкладки. Между вкладками передаются уведомления об изменении; сервер проверяет каждую попытку независимо от состояния браузера.
- Активная видимая страница сверяет таймер с сервером раз в 30 секунд, поэтому отключение ограничения в настройках подхватывается без перезагрузки. Ежесекундных запросов нет.
- Потерянный ответ сверяется запросом состояния; автоматической повторной отправки смены или блокировки нет.

Пауза не регулирует входы непосредственно на внешней площадке и не заменяет существующие ожидания публикации/выгула или охлаждение аккаунта перед повторной выдачей.

## Контракт

- `GET /api/worker/account-action-cooldown` — состояние текущего пользователя, без кеширования.
- `GET /ordersDetails/account-action-cooldown` — эквивалент для включённого legacy-интерфейса с сессионной авторизацией.
- `GET/PUT /api/admin/dictionaries/worker-account-action-settings` — настройка `{enabled, cooldownSeconds}`, только `ADMIN/OWNER`. Старый PUT без `enabled` сохраняет текущий переключатель.
- Ключи в `app_settings`: `worker.account-action.cooldown-enabled` и `worker.account-action.cooldown-seconds`.
- Миграции: `V1_10_286__worker_account_action_cooldown.sql` и `V1_10_287__worker_account_action_cooldown_enabled.sql`.

Состояние содержит `enabled`, `durationSeconds`, `remainingSeconds`, `availableAt` и `serverNow`. В состоянии специалиста `enabled` учитывает и переключатель, и положительную длительность; `durationSeconds` сохраняет настроенное значение даже при выключенном таймере. Времена передаются в UTC. Ответы принятых действий и HTTP 429 содержат заголовки `X-Worker-Account-Action-*`; HTTP 429 также содержит `Retry-After`. Перед отправкой ответа принятого действия состояние перечитывается с сервера, чтобы медленный подбор аккаунта не восстанавливал уже отключённый таймер и не запускал полную паузу повторно в браузере. При ошибке этого чтения используется исходное состояние с исходным `serverNow`, чтобы не подменить более свежую настройку в браузере; результат самого действия сохраняется.

Допуск и чтение настройки используют отдельный пул максимум из двух подключений на экземпляр backend, с конфигурацией подключения основной БД. Это позволяет проверить таймер, когда бизнес-транзакции заняли весь основной пул. Для операций таймера используется `READ_COMMITTED`, чтобы чтение состояния не возвращало старый снимок до последнего принятого действия.

## Проверки

Проверки backend охватывают границы настройки, исключения для привилегированных ролей, одновременный допуск из разных экземпляров сервиса, занятый основной пул, сохранение допуска после отката, ошибки подбора и заголовки ответов 200/204/409/429. Для интеграционных тестов нужны JDK 26 и Docker с MySQL.

Проверки Angular охватывают общий таймер, все пути ручных действий, переходы, вкладки, смену пользователя, потерянный/медленный ответ и изменение настройки. Production-сборка проверяет шаблоны кнопок и административной формы.

Старый интерфейс проверяется отдельно после установки зависимостей frontend:

```powershell
node --test backend/src/test/js/worker-account-action-cooldown.test.cjs
```
