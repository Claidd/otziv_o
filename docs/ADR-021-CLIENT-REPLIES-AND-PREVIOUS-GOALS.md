# ADR-021. Реакции в клиентском чате и вчерашние цели в аудите

Владелец классификации ответа — messaging (`client_chat_control`).
`ClientChatReplyEvidence` предоставляет management только чистую проверку текста:
является ли событие отдельной реакцией или сообщением из одних символов реакции.
Проверка не читает переписку, не меняет карточки и не подтверждает качество обычного
текстового ответа. Её вызывают серверные расчёты времени ответа и сам контроль чата;
пользовательского HTTP-доступа нет.

Владелец итогов дня — reporting (`worker_performance`). `FinalWorkerDayResults`
читает сохранённые результаты только для переданных идентификаторов специалистов
и даты. API возвращает скалярные значения цели и выполнения без ORM-моделей,
изменения результата или доступа к сообщениям. Management выбирает специалистов
назначенного менеджера и вызывает API при подготовке личного аудита; доступ к этому
пути ограничен существующим серверным заданием и разрешениями аудита. Чтение
участвует в транзакции подготовки отчёта, но само не записывает данные.

Событие реакции не закрывает ожидание ответа клиента. Не достигнутая накануне
цель выводится в отчёте и даёт отдельный обязательный вопрос менеджеру. Если
снимок итогов дня отсутствует, API не выводит предположение о невыполнении цели.
