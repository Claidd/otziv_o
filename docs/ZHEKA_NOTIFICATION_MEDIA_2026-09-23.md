## Как ограничивается отправка

- Новые поздравления публикуются после фиксации бизнес-транзакции; при откате отправки нет. Перед отправкой заново проверяются карточка, её состояние и назначенный специалист.
- Подсказки об открытой карточке, пустом тексте, закрытом несохранённом редакторе и серверной ошибке поступают из веб-интерфейса. Старые версии мобильного приложения не генерируют эти интерфейсные сигналы. Подтверждённые серверные действия работают независимо от клиента.
- Подсказка MAX — условная памятка после копирования пароля. Приложение не наблюдает внешний экран авторизации. Подсказки об оформлении профиля при подготовке свежего аккаунта не являются подтверждением, что внешняя аватарка уже загружена.
- Клиентские чаты и неоплаченные заказы менеджера проверяются при тематическом обходе с 17:00. При наличии обоих поводов сначала выбирается чат без ответа.
- Контекстные карточки и прежние тематические напоминания используют общий дневной лимит `worker.thematic-notifications.max-per-day` (по умолчанию 2). Один повод отправляется не более одного раза за день; есть отдельные ограничения частоты категории. Обычные отчёты сохраняют прежние правила.
- Картинка случайно выбирается среди активных изображений своей категории. При нескольких вариантах последняя успешно отправленная этому чату картинка исключается из следующего выбора.
- Картинки дополняют существующий каталог; прежние изображения и настройки категорий сохраняются. Новые категории имеют вероятность 100% и интервал 360 минут. Категория №059 выключена.
- Переключатель `notification-media.contextual.enabled=false` отключает новые контекстные отправки.

## Контракт модулей

Владелец `notification_media` экспортирует только неизменяемый `notification_media.api.StaffMediaSignal`. Авторизованные команды `worker_activity` публикуют скалярный контекст без паролей, текста отзывов и токенов. Слушатель использует `AFTER_COMMIT`; отправка выполняется отдельным ограниченным executor и не меняет результат рабочей команды.

`config.settings.api.ContextualMediaSettings` предоставляет только флаг и общий дневной бюджет. `r_review.utils.ReviewTextPolicy` экспортируется как чистая функция определения пустого/служебного текста; она не даёт прав на карточки и не обращается к БД. `u_users.api.DeferredUserAuthority` определяет отправителя интерфейсного сигнала по аутентификации.

`POST /api/worker/notification-media/context` доступен только обычному специалисту; менеджер, владелец и администратор не могут отправить этот сигнал от лица просматриваемого специалиста. API принимает только пять типов интерфейсных наблюдений и никогда не принимает клиентские поздравления, произвольный текст, chatId или recipientId. Карточка проверяется по назначенному специалисту; повторная проверка выполняется непосредственно перед отправкой. Отказ сети подтверждается серверным журналом блокировок.

Дневные заявки сериализуются блокировкой строки получателя до фиксации короткой транзакции. Сетевой вызов выполняется после освобождения блокировки. Неопределённый исход исключения не освобождает заявку для повторной отправки.
