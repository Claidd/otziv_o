## Доставка и совместимость

Операция хранит неизменяемые адресат, текст и ID. Бизнес-транзакция заканчивается до обращения к провайдеру. UNKNOWN и истёкшая аренда разрешают только чтение существующей квитанции; отсутствие записи не разрешает повторную отправку.

Повтор известного отказа до отправки ограничен и требует актуальных полномочий автора и исходного состояния. Изменённый заказ, сумма или входящее сообщение останавливают устаревшую команду. Поздняя положительная квитанция сохраняется без перезаписи нового бизнес-состояния. Успех без ID сообщения остаётся неопределённым.

Новые клиенты передают `X-Otziv-Delivery-Protocol: queued-v1` на четырёх командах. Старый клиент, считающий любой 2xx подтверждением отправки, получает 409 с объяснением уже сохранённой операции; эта проверка не откатывает очередь. Формат и поведение опубликованной Android-73 проверены, но это не заменяет проверку подписанного обновления. Новый ключ взамен потерянного не создавался.

Исходный отчёт с 28 HIGH/CRITICAL сохранён; эффективных неподтверждённых замечаний после проверки нет. Старый C14 adjudicator и свидетельства публикации не переписаны; дополнительная проверка живёт отдельно.

## Штатный деплой и место

Поддерживаемая точка входа остаётся `infrastructure/scripts/prod/deploy-prod.ps1`. Изменённый WhatsApp и Docker observer собираются и публикуются локально; на VPS выполняется загрузка готовых образов. Перед упаковкой ссылки приложения/web/WhatsApp фиксируются по digest. Активируется проверенный Keycloak default, чтобы старое значение env не оставило прежний образ незаметно.

Расчёт места измеряет распакованные tar-слои, сверяет их SHA-256 с diff ID опубликованной OCI-конфигурации и отдельно учитывает размер скачивания. Docker inspect Size не используется как распакованный размер. Повторно используются только полные совпадающие цепочки слоёв из реально установленных образов; изменённый родитель не даёт ложного совпадения. Для новых слоёв заложены скачивание, две распаковки и файловые накладные расходы, для выпуска — одновременные файлы нового/старого комплекта и резервная копия БД. Резерв 1 GiB сохраняется на каждом используемом файловом разделе. Для одного раздела потребности суммируются; существующие образы не удаляются. Проверка выполняется до паузы автозапуска и снова перед распаковкой выпуска. Модель рассчитана на проверенный overlay2; другой storage driver требует отдельной проверки. Размер SQL-backup оценочный и не гарантирует будущий рост БД/логов.

Четыре образа приложения из 7d7bb87d собраны из чистого состояния и прошли сканирование. Новый observer и окончательный комплект сценария деплоя ещё проверяются. Для фактического выпуска пока не посчитан окончательный объём отсутствующих слоёв. Успех проверки одного уже установленного PostgreSQL не означает, что весь релиз поместится.
