# ADR-022: автоматическое одобрение заказа после семи напоминаний

## Решение

Активный заказ общего счета в статусе «На проверке» можно автоматически одобрить
после семи подтвержденно доставленных напоминаний текущего цикла проверки. Это
касается и накопившихся заказов. Одобрение назначает даты, переводит весь заказ
в «Публикацию», фиксирует аудит и ставит клиенту обычное уведомление о начале
публикации с явным пояснением, что замечаний после семи напоминаний не поступило.
Повторная доставка уведомления остается обязанностью существующего outbox.

Планировщик сначала блокирует запись напоминания, затем агрегат заказа и общий
счет. В той же транзакции повторно проверяются счет, участие заказа, статус,
текущий цикл, завершенность доставки и отсутствие паузы восстановления. При
ошибке подготовки публикации счет переводится в режим внимания менеджера.
Восьмое напоминание не отправляется, пока заказ ожидает автоматического решения.

При возражении клиента менеджер может исключить и архивировать весь заказ одной
операцией. Операция доступна только для неоплаченного заказа в неотправленном
общем счете; для счета с платежным состоянием нужен ручной финансовый разбор.

## Границы модулей

- `client_messages.api.ReviewApprovalReminderStates`: вызывается только
  серверным обработчиком общего счета. Выдает кандидатов и неизменяемое
  свидетельство с ID заказа, числом доставленных напоминаний и ключом цикла.
  Блокировка и завершение требуют активной транзакции; кандидатный поиск только
  читает данные. ORM-сущности наружу не передаются.
- `p_products.api.ReviewReminderOrderApprovals`: серверная команда общего счета
  под уже открытой транзакцией. Владелец заказов блокирует заказ, проверяет его
  цикл и паузу восстановления, затем выполняет штатное одобрение и аудит.
- `p_products.api.DisputedOrderArchive`: серверная команда общего счета под уже
  открытой транзакцией. Владелец заказов проверяет отсутствие платежного
  состояния и выполняет штатный переход в архив. Проверка повторяется после
  исключения заказа из счета.
- `review_recovery.api.ReviewRecoveryMessageHold`: владелец заказов запрашивает
  по ID наличие активной задачи восстановления, уже проверив, что статус заказа
  «На проверке». Только чтение, ORM-сущности не передаются.

Права на HTTP-операцию проверяет контроллер общих счетов; эти интерфейсы не
являются публичными HTTP API. Они не обходят существующие финансовые и
транзакционные ограничения.
