# ADR-022: архив после семи напоминаний

## Действующее решение от 24 октября 2026

Владелец заменил автоматическое одобрение общего заказа архивированием.
Для обычных заказов и позиций общего счёта в статусе «На проверке» действует
одно правило: семь подтверждённых напоминаний текущего цикла, затем один интервал
для ответа (не менее двух дней). Восьмое напоминание не отправляется.
Прежние задания архивирования только по возрасту 30 дней завершаются без
изменения заказа. Старое поле срока остаётся в DTO для совместимости, UI его
больше не предлагает. Автоматическое одобрение публикации не запускается.

Перед архивом читается полная доступная история нужного WhatsApp-чата.
Ответ клиента, неразобранное входящее сообщение, недоступная/неполная история,
оплата, работа по заказу, восстановление отзывов или незавершённая отправка
останавливают архив. После сетевой проверки короткая транзакция повторно
проверяет заказ, текущий цикл и счётчики под блокировками.

Позиция общего счёта сохраняется с отметкой времени и неактивным участием.
Из действующей суммы она исключается, исходные значения сохраняются в аудите.
Платёжные данные и строки состава не удаляются. Когда действующих позиций нет,
счёт архивируется. Отправленный счёт или счёт с платёжными данными требует сверки.

В той же транзакции сохраняются архив, доказательства, очередь уведомлений
клиенту, группе менеджера, активным владельцам и администраторам. Идентификатор
уведомления постоянный; повтор не меняет его текст или получателя. Неизвестный
результат WhatsApp допускает только поиск квитанции; неизвестный Telegram не
переотправляется. Внешние отправки выполняются после фиксации транзакции.

Используется существующий ARCHIVE_REORDER_OFFER для компании «На стопе» без
других активных заказов/открытой заявки. Срок из настроек (по умолчанию три месяца
плюс разброс до десяти дней) отсчитывается от текущего архивирования заказа,
даже если компания давно находится на стопе. Существующая очередь переносится
не раньше этого срока; отправки с неизвестным результатом остаются на сверке.
Счётчик успешных сообщений и дата прежнего статуса компании сохраняются.
В уведомлении ответственным указывается дата
постановки либо конкретная причина отсрочки, а не обещание уже отправленного сообщения.

## Контракты модулей

- `client_messages.api.ReviewReminderClosure`: серверные планировщик общего
  счёта и обработчик кнопки контроля; поиск кандидатов только чтение,
  архив сам владеет транзакцией. Не принимает адресов или текста от HTTP-клиента.
- `client_chat_control.api.ReminderContactHistory`: только чтение истории и
  неразобранных сообщений. Адрес взят из серверного снимка заказа; ошибка не
  интерпретируется как отсутствие ответа.
- `u_users.api.AutomationNoticeRecipients`: владелец пользователей возвращает
  скалярные chat ID активных ответственных по серверному manager ID. Только чтение.

# ADR-022: автоматическое одобрение заказа после семи напоминаний

## Решение

Активный заказ общего счета в статусе «На проверке» можно автоматически одобрить
после семи подтвержденно доставленных напоминаний текущего цикла проверки. Это
касается и накопившихся заказов. Одобрение назначает даты, переводит весь заказ
в «Публикацию», фиксирует аудит и ставит клиенту обычное уведомление о начале
публикации с явным пояснением, что замечаний после семи напоминаний не поступило.
Повторная доставка уведомления остается обязанностью существующего outbox.

Планировщик сначала блокирует запись напоминания, затем агрегат заказа и общий
счет. В той же транзакции повторно проверяются счет, участие заказа, статус,
текущий цикл, завершенность доставки и отсутствие паузы восстановления. При
ошибке подготовки публикации счет переводится в режим внимания менеджера.
Восьмое напоминание не отправляется, пока заказ ожидает автоматического решения.

При возражении клиента менеджер может исключить и архивировать весь заказ одной
операцией. Операция доступна только для неоплаченного заказа в неотправленном
общем счете; для счета с платежным состоянием нужен ручной финансовый разбор.

## Границы модулей

- `client_messages.api.ReviewApprovalReminderStates`: вызывается только
  серверным обработчиком общего счета. Выдает кандидатов и неизменяемое
  свидетельство с ID заказа, числом доставленных напоминаний и ключом цикла.
  Блокировка и завершение требуют активной транзакции; кандидатный поиск только
  читает данные. ORM-сущности наружу не передаются.
- `p_products.api.ReviewReminderOrderApprovals`: серверная команда общего счета
  под уже открытой транзакцией. Владелец заказов блокирует заказ, проверяет его
  цикл и паузу восстановления, затем выполняет штатное одобрение и аудит.
- `p_products.api.DisputedOrderArchive`: серверная команда общего счета под уже
  открытой транзакцией. Владелец заказов проверяет отсутствие платежного
  состояния и выполняет штатный переход в архив. Проверка повторяется после
  исключения заказа из счета.
- `review_recovery.api.ReviewRecoveryMessageHold`: владелец заказов запрашивает
  по ID наличие активной задачи восстановления, уже проверив, что статус заказа
  «На проверке». Только чтение, ORM-сущности не передаются.

Права на HTTP-операцию проверяет контроллер общих счетов; эти интерфейсы не
являются публичными HTTP API. Они не обходят существующие финансовые и
транзакционные ограничения.
