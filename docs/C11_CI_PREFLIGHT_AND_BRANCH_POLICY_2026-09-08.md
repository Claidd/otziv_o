Этот этап исправляет отказ подготовки аудита на C10
`219fa48d628c7650651703637b85a53cc5b0f724` и разделяет проверку защиты

## Причина отказа Maven

В [Dependency audit C10](https://github.com/Claidd/otziv_o/actions/runs/34189630340)
оба дополнительных этапа аудита завершились с кодом 2 до анализа:
`Build-support audit preflight failed: MAVEN_ARGS must be empty`.
Это подтверждено двумя строками журнала задания `101945033121`.
Предупреждения компилятора об устаревших Java-методах не были причиной этого
отказа. Первичный OWASP-этап данного задания завершился успешно; дополнительные
проверки build-support и issuer на C10 не установлены.

Обновлённый `setup-java` по умолчанию добавляет `-ntp` в `MAVEN_ARGS`.
Наш аудит запрещает неявные аргументы Maven, чтобы окружение не могло изменить
полноту проверки. Во всех шести вызовах Actions задан
`show-download-progress: true`: действие перестаёт добавлять переменную.
Явный `-ntp` в командах Maven сохранён. Уже заданные внешние аргументы по-прежнему
приводят к отказу; код защитной проверки не изменён.

Поведение подтверждено
[исходником точной версии setup-java](https://github.com/actions/setup-java/blob/dd06d9cba3e5552c54d9f8ea23572deb30010f7c/src/maven-args.ts).
Зависимости, исключения сканеров и пороги аудита этим исправлением не изменяются.

## Защита ветки и приёмка

Verifier P21 отдельно устанавливает происхождение всех 20 обязательных
проверок, фактические настройки защиты `main` и результаты CI на явно заданном
текущем SHA pull request. Источник привязки — опубликованный C9 в PR №2;
GitHub Actions app ID определяется через API и сверяется с заданиями и
check-runs соответствующих PR-workflow. Результат push с тем же названием
не заменяет результат PR.

Защита ветки должна продолжать действовать при красном CI. Поэтому неуспешный
аудит допускает подтверждение происхождения проверки и включение её в
обязательную политику, но блокирует приёмку коммита. Давность, неоднозначность,
пропуск, отмена или незавершённость проверок также не дают успешной приёмки.
Verifier выполняет только GET; изменение настроек и их повторное чтение
фиксируются отдельно. Подробный порядок — в
[R10](R10_CI_AND_REPOSITORY_CLEANUP.md).

Фактическая защита `main` включена в 05:47 UTC и независимо подтверждена
verifier в 05:48:25 UTC: `ENFORCEMENT_VERIFIED`. Все 20 checks привязаны к
проверенному GitHub Actions app ID `15368`; strict checks и применение к
администратору включены, force push и удаление запрещены.
[Публичное доказательство](../infrastructure/runtime-security/P21_BRANCH_PROTECTION_2026-09-08.json)
содержит точные имена, app/check/run IDs, настройки и хеши наблюдений.
P21 в части обязательных checks на сервере закрыт. Приёмка C10 остаётся
`BLOCKED` из-за двух аудитов; защита не выдаётся за успешный выпуск.
