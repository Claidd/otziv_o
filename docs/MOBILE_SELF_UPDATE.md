# Самостоятельное обновление Android

## Как это работает

1. Backend хранит один актуальный APK и метаданные версии в `/app/mobile-releases`.
2. Android-приложение проверяет `GET /api/mobile-update` при запуске и возвращении из фона.
3. Если `versionCode` на сервере выше установленного, приложение показывает окно обновления.
4. APK скачивается через Android DownloadManager.
5. Перед установкой приложение проверяет SHA-256, package name, versionCode и сертификат подписи.
6. Android открывает системное подтверждение установки. Полностью скрытая установка без MDM невозможна.

## Первый переход

Версия `1.0.53` ещё не умеет проверять обновления. Первый APK с обновлятором (`1.0.54` или новее) нужно один раз установить вручную поверх `1.0.53`. Подписи совместимы, поэтому удалять приложение и терять локальные данные не нужно. Автоматический сценарий начинается со следующей опубликованной версии.

## Публикация

Обычный `infrastructure/scripts/prod/deploy-prod.ps1` автоматически находит подписанный APK с максимальным `versionCode` по маске `mobile/builds/otziv-prod-release-v*-code*.apk`. До Docker build, упаковки deploy-бандла и обращения к VPS скрипт через Android SDK проверяет подпись, package name и внутренние `versionCode`/`versionName`; имя файла не считается доверенным источником. Перед упаковкой также проверяется версия на VPS:

- если такая или более новая версия уже существует, APK повторно не отправляется;
- если файла нет, APK и `release.json` включаются в deploy-бандл;
- после успешной проверки SHA-256 новый APK публикуется атомарно;
- все старые APK сразу удаляются, в хранилище остаётся только актуальный файл.

Для выбора конкретного файла используется `-MobileApkPath <path>`. Чтобы выполнить deploy без публикации мобильной версии, используется `-SkipMobileApkUpload`.

Ручная публикация также доступна через веб-админку `Главная -> Обновление Android`: выбрать APK, указать точные `versionCode` и `versionName`, заполнить описание и нажать `Опубликовать обновление`.

Опция `Минимальная версия` делает обновление обязательным для приложений с меньшим `versionCode`, даже если общий переключатель обязательности выключен.

## Подпись

Постоянный ключ находится в `C:\Users\Hunt\.android\otziv-release.jks`, настройки Gradle — в игнорируемом файле `mobile/android/keystore.properties`. Оба файла нужно хранить в защищённой резервной копии. Потеря ключа сделает установку будущих версий поверх текущего приложения невозможной.

Сертификат SHA-256:

`A1:5A:16:2A:FE:1F:80:8F:95:86:DD:3F:12:9F:9E:61:F4:BE:49:CC:FF:70:8C:A9:9C:6A:07:14:00:42:51:D5`

Полная процедура безопасной сборки, проверки, backup/restore drill и правила
ротации описаны в `docs/ANDROID_RELEASE_SIGNING.md`.

## Серверное хранилище

Compose монтирует `./data/mobile-releases` в `/app/mobile-releases`. Каталог переживает пересборку контейнера. Nginx и Spring принимают APK до 100 МБ. Старый APK удаляется после успешной публикации нового.
