# Переход Android-приложения на новый ключ подписи

## Причина и граница совместимости

Исходный ключ, которым подписан APK `1.0.73` (`versionCode 73`), не найден на доступных дисках и старом компьютере. Его публичный отпечаток SHA-256: `A15A162AFE1F808F9586DD3F129F9E61F4BE49CCFF708CA99C6A0714004251D5`. Владелец разрешил выпуск с новым ключом и ручной переустановкой 16 октября 2026 года.

Новый сертификат имеет SHA-256 `00E249AB3D6A15F051C70F66B726047FCC534FC358E409A2099B4C4C461F9218`. Android не разрешает обновить установленный APK с другой подписью. Старое приложение также проверяет подпись перед установкой. Установить новую версию можно только после удаления старой: локальная сессия и настройки исчезнут, затем потребуется войти заново. Данные на сервере не удаляются.

## Два канала выпуска

- `/api/mobile-update` и его APK остаются на старой подписи и версии `1.0.73`. Административная загрузка новых APK в этот канал закрыта на сервере; скачивание прежней версии сохранено. Не публиковать в этом канале APK с новым сертификатом и не выставлять обязательное обновление на него.
- Новое приложение читает `/android-new/release.json`. Страница `/android-new/` объясняет переустановку; APK скачивается по отдельной ссылке `/android-new/otziv-v1.0.75.apk`.
- Для следующих версий нового приложения обновлять отдельные метаданные и APK с тем же новым сертификатом. Пока существуют установки со старой подписью, старый канал должен оставаться совместимым с ними.

## Ключ и восстановление

Основной JKS и файл свойств для сборки находятся вне репозитория в закрытых каталогах текущего профиля Windows. Проверенные копии JKS лежат на дисках D и E; копия свойств есть на D. Ни JKS, ни пароли нельзя добавлять в Git, CI-логи, PR или пользовательскую инструкцию. При переносе на другой компьютер изменить `storeFile` в восстановленном файле свойств и сверить публичный отпечаток сертификата до сборки.

Перед новым выпуском проверить исходники, точный CI для `main`, подпись, package `com.hunt.otziv`, `versionCode`, SHA-256 APK и резервную копию базы. Штатный `deploy.ps1 -MobileApkPath` заменяет старый канал и для нового сертификата запрещён. Использовать отдельный параметр `-StandaloneMobileApkPath` и проверку файла `frontend/public/android-new/release.json`.

После установки новой версии на устройстве проверить вход, начисления, платежи, push-уведомления и последующее обновление из нового канала. Предупредить сотрудников о необходимости помнить данные для входа **до удаления** старого приложения.
